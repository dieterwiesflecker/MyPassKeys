# Configuration, Infrastructure & Conventions

## Configuration reference

`appsettings.json` keys:
- `ConnectionStrings:Postgres`, `ConnectionStrings:Redis`
- `Jwt:Issuer`, `Jwt:Audience` — fallbacks when a resolved tenant carries no issuer/audience.
- `MyPassKeys:DeploymentHosts` — hostnames where THIS installation is reachable; the host-gate middleware 404s anything else. Required (startup throws if empty).
- `MyPassKeys:BootstrapManagementOrigins` — `AllowedOrigins` seeded onto a fresh management tenant. Used only on the very first startup; ignored once the management tenant exists.
- `MyPassKeys:BootstrapManagementIssuer` / `BootstrapManagementAudience` — JWT issuer/audience seeded onto a fresh management tenant. Defaults to `https://{firstDeploymentHost}` / `api://{firstDeploymentHost}`. Same one-shot semantics.
- `MyPassKeys:IssuerBaseUrl` — base URL used to auto-derive each new tenant's immutable `JwtIssuer` as `{base}/t/{tenantId}`. Defaults to `https://{firstDeploymentHost}`. Resource servers must use this same base when reconstructing the expected issuer from `tenant_id`.
- `MyPassKeys:MaxTenantsPerUser` — per-user cap on self-service tenant creation (default 10; 0 disables). Counts tenants where the caller already holds `tenantadmin`, excluding the management tenant; `POST /tenants` returns 429 when exceeded.
- `MyPassKeys:KeyEncryptionKey` — **required** base64 32-byte KEK that encrypts tenant JWT signing private keys at rest. Dev value lives in `appsettings.Development.json`; production supplies it via `MyPassKeys__KeyEncryptionKey` (compose.prod.yaml reads `KEY_ENCRYPTION_KEY` from the server's `.env`, auto-generated by `deploy.sh` if missing). Never store it in the database. `MyPassKeys:PreviousKeyEncryptionKeys` (string array) accepts retired KEKs during rotation.
- `Tenant:BootstrapOwnerEmail` — the email guaranteed to be a `tenantadmin` in the management tenant. Re-applied on **every** startup.
- `Resend:ApiKey`, `Resend:FromEmail` — outbound email for verification codes.
- `.env` — API keys, database credentials, Redis password (used by docker-compose).

**Forwarded headers**: `ForwardedHeaders:KnownNetworks` (CIDR list) and `ForwardedHeaders:KnownProxies` (IP list) in appsettings control which proxies are trusted to set `X-Forwarded-*`. When both lists are empty, the framework falls back to loopback only — direct callers cannot spoof `X-Forwarded-For` to bypass IP-based rate limiting. Production must populate these (Docker bridge CIDR, Cloudflare ranges, etc.) or `RemoteIpAddress` will be the reverse proxy's IP.

## Minimal API routing

Endpoints organized via `MapGroup` in static classes (`Fido2Endpoints`, `TenantEndpoints`, `PortalEndpoints`, `UserEndpoints`, `RoleEndpoints`, `GroupEndpoints`, `AdminEndpoints`, `EmailVerificationEndpoints`, `DebugEndpoints`). New endpoint groups follow the `MapXxxEndpoints` extension pattern and **must be wired in `Program.cs`** alongside the existing `app.MapXxxEndpoints()` calls. `DebugEndpoints` (`/debug/token`, which decodes any token's claims **without authentication**) is wired only when `app.Environment.IsDevelopment()` — never expose it in production.

## AOT serialization

The app uses `WebApplication.CreateSlimBuilder` with source-generated JSON via `AppJsonSerializerContext` in `Program.cs`. **Every new request/response DTO must be added to a `[JsonSerializable(typeof(...))]` attribute on `AppJsonSerializerContext`** or it will fail at runtime in published builds.

## Username/email normalization

Inconsistent across the code today. When adding code that touches `Fido2AppUser.Username`, normalize at the API boundary with `.Trim().ToLowerInvariant()` before lookups, storage, or Redis key construction. The Marten unique index on `(TenantId, Username)` is case-sensitive.
